# 案例：会议记录生成工作台

> 在飞书妙搭上为一个安全委员会秘书做的内部工具的公开版写作。公司、部门、出席者和文件一律不披露；demo 展示系统，不展示数据。

## 问题

部门安全委员会每年开几次会。秘书录音，然后按一套沿用多年的固定 Word 格式整理会议记录：首页是日期、时间、地点、出席名单和抄送名单；接着是七个固定编号的章节，正文两栏（内容 | 行动）。第三节带一张小统计表，附千人意外率的公式注解。整份文件是嵌套表格，以往每次都是复制上一份再逐字改。

慢在两处。会议是粤语，转写工具出来的文本仍要人手分节。Word 格式又极不宽容：一段贴进去样式不对，整页就走样，秘书得逐段修。

工具上线前每份记录耗时：`[TO FILL]`。每年会议次数：`[TO FILL]`。

## 做了什么

一个妙搭应用，两页。

**第一页 · AI 助手。** 页内嵌一个 Aily 智能体。秘书把转写文本贴进去，智能体返回 JSON：`sections[] { no, title, items[] { subtitle, content, action, uncertain, uncertain_note, safety_table } }`。听不清的地方标 `uncertain` 并附说明，不猜。公开 demo 只复刻面板形态，任何消息都返回 "Not available in public demo"。

**第二页 · 工作台。** 一页三步，纵向流式，没有导航：

1. **粘贴 JSON。** 每次输入即时校验。智能体的输出偶尔带 ```` ```json ```` 围栏或开头一句话，所以先清洗：去围栏，取最外层 `{ … }`。
2. **预览结构。** 七行表，一节一行，显示条目数、是否附统计表、是否含待确认项。JSON 里缺的节标"缺失"；JSON 里多出来、不在七节之内的章节列为"非预期，将被忽略"。高亮用琥珀色不用红色：待确认是提醒复核，不是报错。
3. **生成并下载。** 一个按钮。文件名刻意把会议次数留成 `X`——次数来自粤语语音，是最常转写错的字段，所以不从 JSON 带入，交给秘书下载后手改。最近五份文件留在历史列表里。

## 工程决策

### JSON 报错给出行列号

秘书需要知道贴错在*哪*。新版 V8 的 `JSON.parse` 错误信息不再保证带位置。工作台先解析原生信息（`line N column M` 或 `position N`），两者都没有时退到一个手写的小型 JSON 扫描器（`json-error-locate.ts`），逐字扫描并用中文说明第一个出错字符（"預期為逗號 , 或 }"）。约 150 行，无依赖，结果确定。

### 克隆带格式的行，而不是重定义样式

第一版用 `python-docx` 按样式重建文档，始终和原件对不齐，而且线上运行时是 Node FaaS，根本没有 Python。重写后的 `build-minutes.js` 用 jszip 打开母版，用 xmldom 解析 `word/document.xml`，把母版里特定的几行当作*供体*：一行节标题、一行空白间隔、一行内容、一行段落里带粗体下划线小标题样式和项目符号样式。生成过程是：清空首页字段，从第 7 行起删掉全部正文行，再为七节各追加一个克隆的标题行、一个间隔行、每个条目一个克隆的内容行，只换文本节点。字体、边框、缩进、编号没有一处是代码写的，输出不可能偏离母版。

统计表同理：母版里的整块（外层 1×1 表格套一张 3×5 表格和公式注解）整体克隆，保留表头行，数据行从第一行数据克隆，最后补一个空段落——Word 不允许单元格以表格结尾。

### 章节匹配先标题后节号

智能体有时写 `（一）`，有时写 `一`。生成器和预览用同一条规则：先按标题匹配，再按去掉括号的节号兜底。两者都基于生成器导出的同一份固定 `SECTIONS` 列表，预览不可能和实际生成结果不一致。

### 在平台拦截器之下从 NestJS 返回二进制

控制器直接 `return Buffer` 会得到损坏的下载：平台的全局拦截器把它 JSON 序列化成了 `{"type":"Buffer","data":[…]}`。下载接口改用 `@Res()`，自己写 `Content-Disposition` 和字节。

### 静态引用才能活过依赖裁剪

第一次发布线上 500，`Cannot find module 'jszip'`。平台构建用 `@vercel/nft` 从入口文件静态追踪 `require` 来裁剪 `node_modules`。生成模块当时用 `createRequire` 加动态路径加载，jszip 从未被追踪到。改成静态 `import`（JS 旁边放一个 `.d.ts` 提供类型）后解决。验证也成了固定动作：本地跑一遍裁剪脚本，再从裁剪产物里 `require` 这个模块。

### 没做的

没有数据库、没有用户系统、不持久化生成的文件。进程内存里留五条，重启即清。秘书当场下载，没什么需要存。

## 公开 demo

同一份页面代码，三处替换：

- NestJS 服务换成客户端模块：拉取母版、在浏览器里跑同一个生成器、保留同样的五条历史。
- 母版保留 XML 结构——生成器依赖行的位置——但每一个值都换成全角下划线。logo 图片、自定义 XML 和文档作者元数据删除。
- Aily 面板是视觉复刻，没有应答器。

没有任何虚构：没有替身部门，没有虚构出席者，没有从真实页面抄来的示例统计。示例 JSON 是为 demo 写的通用安全措辞。

## 结果

工具上线后每份记录耗时：`[TO FILL]`。秘书的复核从排版转向内容：琥珀色的"待确认"行直接告诉他们该对照录音检查哪几句。
